# Политики

> **Уровень B.** Сначала прочитайте: [Руководство](guide.md#1-создайте-шину), шаги 1–3.

Эта страница нужна, когда обработчики накладываются друг на друга в SPA (поиск по мере набора, двойная отправка, уход со страницы). **Политика** оборачивает обработчик и решает, что делать в этом случае.

Начните с `latest`. Таблица и разделы ниже — остальной справочник.

## Прервите предыдущий запуск

```js
import { createBus } from "nanoeffects";
import { latest } from "nanoeffects/policies";

const bus = createBus();

// latest — новый запуск прерывает старый
bus.on(
  "search",
  latest(async (query, { signal }) => {
    // signal — позволяет latest отменить этот запрос, а не только отбросить его результат
    await api.search(query, { signal });
  }),
);
```

Передайте `signal` в `fetch` (и подобные вызовы), чтобы запрос отменялся.

## Выберите политику

Каждая политика принимает `key` в параметрах (см. [Раздельное состояние по ключу](#раздельное-состояние-по-ключу)).

| Политика | Накладывающиеся вызовы |
| -------- | ---------------------- |
| `latest(fn)` | предыдущий запуск прерван, результат отброшен |
| `leading(fn)` | новые вызовы отбрасываются, пока идёт запуск |
| `debounce(ms, fn, options?)` | запуск после `ms` тишины |
| `throttle(ms, fn, options?)` | не больше одного запуска за `ms` |
| `queue(fn, options?)` | один за другим, по порядку |

У каждой политики есть краткая запись в разделе [Найти политику](#найти-политику).

## Найти политику

Одна запись на политику: что она делает, её сигнатура и раздел с полным рецептом.

### `latest`

Новый вызов прерывает старый и отбрасывает его результат. `latest(fn, options?)`. Полный рецепт: [Прервите предыдущий запуск](#прервите-предыдущий-запуск).

### `leading`

Новые вызовы отбрасываются, пока идёт запуск. `leading(fn, options?)`. Используйте для защиты от двойной отправки: [Защита от двойной отправки](prevent-double-submit.md).

### `debounce`

Запускается после `ms` тишины. `debounce(ms, fn, options?)`. Параметры (`leading`, `trailing`): [Настройка debounce и throttle](#настройка-debounce-и-throttle).

### `throttle`

Не больше одного запуска за `ms`. `throttle(ms, fn, options?)`. Параметры: [Настройка debounce и throttle](#настройка-debounce-и-throttle).

### `queue`

Вызовы идут один за другим, по порядку. `queue(fn, options?)`, а `concurrency` позволяет запускать несколько сразу. Полный рецепт: [Вызовы один за другим через `queue`](#вызовы-один-за-другим-через-queue).

### `key`

Параметр каждой политики: у каждого ключа своё состояние, поэтому вызовы с разными ключами не влияют друг на друга. `latest(fn, { key: (payload) => payload.id })`. Полный рецепт: [Раздельное состояние по ключу](#раздельное-состояние-по-ключу).

### `withPolicy`

Превращает политику в обычную функцию, которой не нужна шина. `withPolicy(debounce(300, fn))`. Полный рецепт: [Политика без шины](#политика-без-шины).

## Вызов политики без её функции

**Проблема.** Некоторый код сам строит функцию и спрашивает только, какую политику использовать, как это делает [`usePolicy`](react.md#сохраните-обработчик-с-debounce-между-рендерами). Если вам приходится передавать туда собственную функцию, легко передать не ту.

**Когда.** Вы передаёте политику в `usePolicy`. С шиной, `withPolicy` или вашим собственным кодом вызывайте политику с её функцией, как выше.

Опустите функцию, и политика вернёт обёртку. Обёртка принимает функцию и возвращает ту же политику, что и прямой вызов:

```js
import { debounce } from "nanoeffects/policies";

const runSearch = async (query) => {
  await api.search(query);
};

// debounce(300) — функции ещё нет: возвращает обёртку
const wrap = debounce(300);

// обёртка принимает функцию; то же, что debounce(300, runSearch)
const search = wrap(runSearch);
```

- Работает для `latest()`, `leading()`, `debounce(ms)`, `throttle(ms)` и `queue()`, а параметры идут последним аргументом: `queue({ concurrency: 2 })`, `debounce(300, { leading: true })`.
- Каждый раз, когда вы применяете обёртку к функции, вы получаете новую политику со своим состоянием.
- Чтобы объединить политики, вкладывайте их, как раньше: `throttle(100, latest(fn))`.
- С `key` в TypeScript аннотируйте нагрузку у функции ключа: `latest({ key: (user: User) => user.id })`. Без аннотации обёртка не может знать тип нагрузки.

## Настройка debounce и throttle

`debounce` и `throttle` принимают `leading` и `trailing`. Поведение совпадает с lodash (и patronum); тесты сравнивают случайные последовательности вызовов с самим lodash.

**Throttle** (`throttle(ms, fn)`):

- По умолчанию `leading: true`, `trailing: true`.
- Вызов, когда throttle простаивает (прошло не меньше `ms` после предыдущего вызова и запуска), выполняется сразу.
- Вызовы, сделанные во время ожидания, удерживаются; последний выполняется, когда окно закрывается.
- При стабильном потоке запуск идёт каждые `ms`.
- `leading: false`: даже первый вызов ждёт конца своего окна.
- `trailing: false`: вызовы, сделанные во время окна, отбрасываются.

**Debounce** (`debounce(ms, fn)`):

- По умолчанию `trailing: true`: последний вызов выполняется после `ms` тишины.
- `leading: true`: первый вызов серии тоже выполняется сразу; завершающий запуск происходит, только если следуют ещё вызовы.
- `leading: true, trailing: false`: только первый вызов серии.
- Оба `false`: ничего не запускается.

## Раздельное состояние по ключу

`key` даёт каждому ключу своё состояние. Вызовы с разными ключами не влияют друг на друга. Простаивающие ключи удаляются, поэтому ключей может быть сколько угодно (идентификаторы, URL).

```js
import { createBus } from "nanoeffects";
import { latest, queue } from "nanoeffects/policies";

const bus = createBus();

// один запуск latest на идентификатор пользователя
bus.on(
  "load",
  latest(loadUser, { key: (user) => user.id }),
);

// загрузки одного и того же файла идут одна за другой
bus.on(
  "upload",
  queue(upload, { key: (file) => file.name }),
);
```

## Вызовы один за другим через `queue`

```js
import { createBus } from "nanoeffects";
import { queue } from "nanoeffects/policies";

const bus = createBus();

// queue — один за другим, по порядку
bus.on(
  "save",
  queue(async (draft, { signal }) => {
    await api.save(draft, { signal });
  }),
);

bus.emit("save", draftA); // выполняется сразу
bus.emit("save", draftB); // ждёт draftA, затем выполняется
```

| Параметр | Значение |
| -------- | -------- |
| `concurrency` | сколько вызовов могут идти одновременно (по умолчанию `1`) |
| `limit` | сколько вызовов могут ждать |
| `overflow` | когда очередь полна: `"drop-new"` (по умолчанию) или `"drop-old"` |

Отброшенный вызов завершается значением `undefined`. `queue(fn, { limit: 1, overflow: "drop-old" })` оставляет только последний ожидающий вызов. `limit: 0` не даёт никому ждать.

Каждый вызов возвращает промис с результатом собственного запуска. Ошибка отклоняет только этот вызов; очередь продолжает работу.

**Прерывание:**

- Ожидающий вызов, чья задача прервана, пропускается и завершается значением `undefined`.
- Когда прерывается выполняющийся вызов, его слот освобождается сразу, а результат отбрасывается.
- Передавайте `signal` в то, что делает `fn`. `fn`, который его игнорирует, может пересечься со следующим запуском.

## Политика без шины

**Проблема.** Нужен обработчик ввода с debounce или fetch по принципу «побеждает последний запрос», но в вашем коде нет шины. Политике на каждом вызове нужен контекст, поэтому `debounce(300, search)("re")` сам по себе не работает.

**Когда.** Одному компоненту или модулю нужна политика и больше ничего из библиотеки. Если шина у вас уже есть, проще `bus.on(event, policy)`.

`withPolicy` принимает результат любой политики и возвращает обычную функцию. Ей не нужны ни шина, ни аргумент с контекстом, и она сохраняет состояние политики между вызовами.

```js
import { debounce, withPolicy } from "nanoeffects/policies";

// debounce — ждёт 300 мс тишины, затем запускает колбэк
const policy = debounce(300, async (query, { signal }) => {
  await api.search(query, { signal });
});

// withPolicy — обычная функция: без шины и без аргумента с контекстом
const onChange = withPolicy(policy);

onChange("re");
onChange("redux"); // выполняется только этот вызов, через 300 мс после него

// cancel — отбрасывает ожидающий вызов и прерывает выполняющийся
onChange.cancel();
```

- У колбэка та же форма `(payload, ctx)`, что и для шины. `ctx.signal`, `ctx.abort` и `ctx.run` работают. `ctx.emit` и `ctx.on` ничего не делают, потому что шины нет.
- Каждый вызов возвращает промис с результатом. Вызов, отброшенный политикой, завершается значением `undefined`.
- `cancel()` прерывает каждый вызов, который ещё не закончился. Вызовы после него снова работают.
- Там, где есть `Symbol.dispose`, `using onChange = withPolicy(policy)` вызывает `cancel()` в конце области видимости.

В компоненте React используйте вместо этого [`usePolicy`](react.md#сохраните-обработчик-с-debounce-между-рендерами): он сохраняет функцию между рендерами.
