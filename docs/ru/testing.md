# Тесты времени диаграммами

> **[Уровень B](README.md#виды-проектов)**: SPA с async UI. Сначала прочитайте: [Политики](policies.md).

Тест `latest`, `debounce`, `queue`, `retry` или `timeout` — это тест времени. С поддельными таймерами время прячется в числах (`advanceTimersByTime(30)`), а список вызовов вы проверяете вручную. Эта страница показывает, как записать расписание и ожидание двумя короткими диаграммами, как это делают marble-тесты RxJS.

Нужен тест-раннер с поддельными таймерами (Vitest или Jest). Сам хелпер его не импортирует.

## Тест политики диаграммой

**Проблема.** Нужен тест, который говорит: второй поиск отменяет первый, и завершается только второй.

**Когда.** Политика или эффект решает, что и когда выполняется, и ответ зависит от времени между событиями.

1. Создайте шину через `createMarbleBus`. Она записывает трассировку своих задач и даёт `run`.
2. Зарегистрируйте обработчик на `marbles.bus`, как в приложении.
3. Вызовите `run` с диаграммой отправок. Один символ — один кадр (по умолчанию 10 мс).
4. Вызовите `expect` с диаграммой фаз, которую ждёте.

```js
// search.test.js
import { it, vi } from "vitest";
import { latest } from "nanoeffects/policies";
import { createMarbleBus, fakeTimersClock } from "nanoeffects/testing";

// поиск, который занимает 50 мс
function search(query) {
  return new Promise((resolve) => setTimeout(resolve, 50));
}

it("latest cancels the search that is running", async () => {
  vi.useFakeTimers();

  // createMarbleBus: шина, которая записывает трассировку, и run, который двигает время по кадрам
  const marbles = createMarbleBus({ clock: fakeTimersClock(vi) });

  // latest: новый поиск отменяет выполняющийся
  marbles.bus.on("search/changed", latest(search), { traceId: "search" });

  // "a-b": отправить "x" в кадре 0 и "xy" в кадре 2
  const result = await marbles.run({
    emits: { "search/changed": { marble: "a-b", values: { a: "x", b: "xy" } } },
    frames: 12,
  });

  // s старт, c отмена, d готово: в кадре 2 второй поиск отменяет первый, и завершается в кадре 7
  result.expect({ "search/changed:latest": "s-(cs)----d----" });
});
```

Когда строка не совпала, `expect` бросает ошибку с двумя диаграммами одна под другой:

```
marble row "search/changed:latest" differs
  expected  s-(cs)----d----
  received  s-(cs)---d-----
```

Такой же тест для `queue` и `debounce` лежит в [`examples/testing`](../../examples/testing). Запустите его командой `pnpm vitest run examples/testing`.

## Чтение диаграмм

В диаграмме один символ или одна группа в скобках на кадр.

| Символ | В `emits` | В результате |
| ------ | --------- | ------------ |
| `-` | ничего не происходит | ничего не происходит |
| буква или цифра | отправляет событие со значением `values[символ]` (без `values` — сам символ) | `s` старт, `d` готово, `e` ошибка, `c` отмена, `x` отброшено |
| `(ab)` | две отправки в одном кадре, в таком порядке | две фазы в одном кадре, в порядке, в котором они произошли |

Другие символы (`|`, пробелы) вызывают ошибку с названием диаграммы и позицией.

У задачи в результате есть строка `type:effect`: `search/changed:latest` — задача политики `latest`, `search:run` — обработчик с именем `search`. Вызовите `result.rows()`, чтобы напечатать все строки, и скопируйте нужные в `expect`. В `expect` можно написать один эффект (`latest`), если он есть в одной строке. Если он есть в двух, ошибка попросит полный ключ.

## Кадр и число кадров

Кадр — 10 мс. Чтобы изменить его, передайте `frame` в `createMarbleBus`. Кадр события — его время, делённое на длину кадра, с округлением вниз: таймер на 100 мс, начатый в кадре 0, заканчивается в кадре 10, поэтому для него нужно `frames` не меньше 11.

`frames` — число кадров для запуска. Без него хелпер выполняет столько, сколько в самой длинной диаграмме `emits`. Работа, которая дольше диаграммы, обрезается, поэтому задавайте `frames`, когда обработчик занимает время.

## Другие часы

`fakeTimersClock(vi)` двигает поддельные таймеры и читает `Date.now()`. Тест включает поддельные таймеры сам (`vi.useFakeTimers()`) и оставляет `Date` поддельным, как по умолчанию. Jest работает так же: `fakeTimersClock(jest)`.

Часами служит любой объект с `advance(ms)` и `now()`. `advance` может вернуть промис.

## Чего нет

- **Нужен трассировщик.** Хелпер читает трассировку шины, поэтому у `nanoeffects/testing` нет сборки `notrace`.
- **Одна строка на все вызовы.** Два вызова одного обработчика делят строку, поэтому `(sd)` показывает порядок фаз, а не то, к какому вызову они относятся.
- **Нет данных в диаграммах.** Диаграмма показывает, когда, а не что. Значения проверяйте тест-раннером как обычно.
- **Не алфавит RxJS.** Нет горячих и холодных источников и нет `|` для конца потока.
