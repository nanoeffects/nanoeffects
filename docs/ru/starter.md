# Проект из шаблона

> **[Уровень A](README.md#виды-проектов)**: небольшое приложение, виджет или MVP.

Одна команда создаёт работающий проект, и Vite с шиной подключать вручную не нужно. Проект — небольшое приложение с полем поиска. Оно ждёт, пока вы перестанете печатать (`debounce`), и прерывает старый запрос при новом (`latest`).

Нужен Node 18 или новее.

## Создание проекта

Замените `my-app` на имя новой папки.

```bash
npm create nanoeffects@latest my-app
```

```bash
pnpm create nanoeffects my-app
```

```bash
yarn create nanoeffects my-app
```

```bash
bun create nanoeffects my-app
```

Если шаблон не указан, команда спросит его. Папка должна быть новой или пустой, иначе команда остановится и не перезапишет файлы.

Затем выполните шаги, которые напечатала команда:

```bash
cd my-app
npm install
npm run dev
```

Откройте адрес, который напечатает Vite, и наберите что-нибудь в поле. Поддельный backend отвечает 800 мс, поэтому видно, как прерывается старый запрос.

## Выбор шаблона

Передайте `--template`, чтобы пропустить вопрос. С npm перед параметром ставьте `--`.

| Шаблон | Что показывает | Когда брать |
| ------ | -------------- | ----------- |
| `vanilla` | Шина, одно событие и обработчик с `debounce` и `latest`, обычный DOM-код | Вы без фреймворка или хотите увидеть одну шину |
| `react` | Тот же обработчик с `useEmitter` и `useEventState`, а также `usePolicy` для сохранения с debounce в компоненте | Вы пишете приложение на React |
| `vanilla-ts` | Приложение `vanilla` на TypeScript | Хотите, чтобы компилятор проверял события и обработчики |
| `react-ts` | Приложение `react` на TypeScript | Вы пишете приложение на React с TypeScript |
| `domains-ts` | Actions с обработчиками, job и модули; логика разложена по доменным папкам, а React — тонкий слой | В приложении больше одной фичи, и логику нужно вынести из UI |
| `vue-ts` | Приложение `react-ts` на Vue 3, с `watchEmitter` и `useEventRef` из `nanoeffects/vue` | Вы пишете приложение на Vue 3 |
| `svelte-ts` | Приложение `react-ts` на Svelte 5, с `eventStore` из `nanoeffects/svelte` | Вы пишете приложение на Svelte |

```bash
npm create nanoeffects@latest my-app -- --template react
```

В шаблонах `react` `useEventState` хранит найденные элементы в компоненте. Это не глобальный стор: другой компонент получит свою копию. Чтобы делить значение между компонентами, возьмите менеджер состояния: [Сторы](stores.md).

TypeScript-шаблоны — те же приложения с теми же файлами в `.ts` и `.tsx`. События создаёт `createAction<Payload>`, поэтому обработчики и `useEventState` берут типы из событий, и аннотации в компоненте не нужны. Перед сборкой `npm run build` проверяет типы (`tsc --noEmit`).

```bash
npm create nanoeffects@latest my-app -- --template react-ts
```

### Начало с Vue

`vue-ts` — приложение поиска из `react-ts` на Vue 3 с `<script setup lang="ts">`. Шина использует `vuePlugin` из `nanoeffects/vue`: `watchEmitter` отправляет запрос в шину при его изменении, а `useEventRef` хранит результат поиска в `ref`. Как и `useEventState` в React, `useEventRef` — [не стор](vue.md#это-не-стор). Значение, общее для нескольких компонентов, храните в сторе, например в Pinia.

```bash
npm create nanoeffects@latest my-app -- --template vue-ts
```

`npm run build` проверяет типы файлов `.vue` через `vue-tsc`. Ему нужен TypeScript 5, поэтому шаблон от него зависит.

### Начало со Svelte

`svelte-ts` — приложение поиска из `react-ts` на Svelte 5. Шина использует `sveltePlugin` из `nanoeffects/svelte`: `eventStore` превращает событие в стор Svelte. В компоненте `$found` читает его, а Svelte сам подписывается и отписывается. Запрос уходит в шину из обработчика `oninput`, поэтому при монтировании компонента ничего не отправляется. Стор слушает, только пока его что-то читает, и [не является стором приложения](svelte.md#это-не-стор-приложения). Значение, общее для нескольких компонентов, храните в своём сторе.

```bash
npm create nanoeffects@latest my-app -- --template svelte-ts
```

`npm run build` проверяет типы файлов `.svelte` через `svelte-check`. Ему нужен TypeScript 5, поэтому шаблон от него зависит.

### Начало с доменами

`domains-ts` — не то же поле поиска на TypeScript. Он показывает, где живёт логика, когда в приложении несколько фич. Каждый домен — папка в `src/domains/`: события домена, их обработка и модуль, который её подключает. React-компоненты только отправляют события и читают значения.

```bash
npm create nanoeffects@latest my-app -- --template domains-ts
```

| Путь | Задача |
| ---- | ------ |
| `src/bus.ts` | Создаёт шину. Не импортирует ни события, ни домены. |
| `src/app.ts` | Подключает домены через `modulePlugin`. |
| `src/domains/catalog/` | Поиск товаров: `catalog.ts` (события и action с обработчиком), `catalog-handlers.ts` (`debounce` и `latest`), `catalog-module.ts`. |
| `src/domains/checkout/` | Оформление заказа: `checkout.ts` (job), `checkout-handlers.ts` (`leading` и `retry`), `checkout-store.ts` (состояние, записываемое из исходов задачи), `checkout-module.ts`. |
| `src/ui/` | Компоненты. Ни один из них не вызывает поддельный backend из `src/api.ts`. |

Пример побольше — чат, где части реагируют друг на друга, — в [Чат с сущностями, фичами, модулями и небольшим backend](chat-example.md). Слоёв там больше, чем в `domains-ts`. Когда домены должны реагировать друг на друга, чат делит их на сущности и фичи, и домены не импортируют друг друга.

Actions, jobs и модули объясняет страница [Actions, jobs и модули](actions.md). Шаблон хранит найденные товары в провайдере Context с одним `useEventState`, а состояние заказа — в отдельном сторе, потому что `useEventState` — [не стор](react.md#последнее-значение-события-как-состояние).

## Файлы

Каждый шаблон, кроме `domains-ts`, делит код как [Руководство](guide.md): один файл — одна задача. В TypeScript-шаблонах файлы имеют расширение `.ts` (`.tsx` у компонентов React, `.vue` у Vue, `.svelte` у Svelte).

| Файл | Задача |
| ---- | ------ |
| `src/bus.js` | Создаёт шину. Не импортирует события. |
| `src/search.js` | Называет события через `createAction`. Не импортирует шину. |
| `src/search-handlers.js` | Обрабатывает события через `debounce` и `latest`. Знает и шину, и события. |
| `src/api.js` | Поддельный backend. Замените его своими запросами. |

Каждый вызов nanoeffects в этих файлах снабжён комментарием. Чтобы адаптировать проект, замените `src/api.js`, затем переименуйте события и обработчик.
