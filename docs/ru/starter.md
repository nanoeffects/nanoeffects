# Проект из шаблона

> **Уровень A.** Сначала прочитайте: ничего, эта страница сама создаёт для вас проект.

Эта страница нужна, когда хочется получить работающий проект одной командой, а не подключать Vite и шину вручную. Команда создаёт небольшое приложение с полем поиска, которое ждёт, пока вы перестанете печатать (`debounce`), и прерывает старый запрос, когда начинается новый (`latest`).

Нужен Node 18 или новее.

## Создайте проект

Выполните команду для вашего менеджера пакетов. Замените `my-app` на имя новой папки.

```bash
npm create nanoeffects@latest my-app
```

```bash
pnpm create nanoeffects my-app
```

```bash
yarn create nanoeffects my-app
```

```bash
bun create nanoeffects my-app
```

Если шаблон не указан, команда спросит его. Папка должна быть новой или пустой: команда остановится, а не перезапишет файлы.

Затем выполните шаги, которые она напечатает:

```bash
cd my-app
npm install
npm run dev
```

Откройте адрес, который напечатает Vite, и наберите что-нибудь в поле. Поддельный сервер отвечает через 800 мс, так что видно, как старый запрос прерывается.

## Выберите шаблон

Передайте `--template`, чтобы пропустить вопрос. С npm перед параметром ставьте `--`.

| Шаблон | Что показывает | Когда брать |
| ------ | -------------- | ----------- |
| `vanilla` | Шина, одно событие и обработчик с `debounce` и `latest`, обычный DOM-код | Вы без фреймворка или хотите увидеть одну шину |
| `react` | Тот же обработчик с `useEmitter` и `useEventState`, а также `usePolicy` для сохранения с debounce в компоненте | Вы пишете приложение на React |
| `vanilla-ts` | Приложение `vanilla` на TypeScript | Хотите, чтобы компилятор проверял события и обработчики |
| `react-ts` | Приложение `react` на TypeScript | Вы пишете приложение на React с TypeScript |
| `domains-ts` | Действия с обработчиками, задача (job) и модули; логика разложена по доменным папкам, а React — тонкий слой | В приложении больше одной фичи, и логику нужно вынести из UI |
| `vue-ts` | Приложение `react-ts` на Vue 3, с `watchEmitter` и `useEventRef` из `nanoeffects/vue` | Вы пишете приложение на Vue 3 |
| `svelte-ts` | Приложение `react-ts` на Svelte 5, с `eventStore` из `nanoeffects/svelte` | Вы пишете приложение на Svelte |

```bash
npm create nanoeffects@latest my-app -- --template react
```

В шаблонах `react` `useEventState` хранит найденные элементы в компоненте. Это не глобальный стор: другой компонент получит свою копию. Чтобы разделить значение между компонентами, используйте менеджер состояния и смотрите [Сторы](stores.md).

TypeScript-шаблоны — те же приложения с теми же файлами, написанные в `.ts` и `.tsx`. События создаются через `createAction<Payload>`, поэтому обработчики и `useEventState` берут типы из событий, без аннотаций в компоненте. `npm run build` проверяет типы проекта (`tsc --noEmit`) перед сборкой.

```bash
npm create nanoeffects@latest my-app -- --template react-ts
```

### Начало с Vue

`vue-ts` — приложение поиска из `react-ts` на Vue 3 с `<script setup lang="ts">`. Его шина использует `vuePlugin` из `nanoeffects/vue`: `watchEmitter` отправляет запрос в шину при его изменении, а `useEventRef` хранит результат поиска в `ref`. Как и `useEventState` в React, `useEventRef` — [не стор](vue.md#это-не-стор): значение, которое делят несколько компонентов, должно лежать в сторе, например в Pinia.

```bash
npm create nanoeffects@latest my-app -- --template vue-ts
```

`npm run build` проверяет типы файлов `.vue` через `vue-tsc`, которому нужен TypeScript 5: от него зависит шаблон.

### Начало со Svelte

`svelte-ts` — приложение поиска из `react-ts` на Svelte 5. Его шина использует `sveltePlugin` из `nanoeffects/svelte`: `eventStore` делает из события стор Svelte. В компоненте `$found` читает его, а Svelte сам подписывается и отписывается. Запрос уходит в шину из обработчика `oninput`, поэтому при монтировании компонента ничего не отправляется. Стор слушает, только пока его что-то читает, и [не является стором приложения](svelte.md#это-не-стор-приложения): значение, которое делят несколько компонентов, должно лежать в вашем собственном сторе.

```bash
npm create nanoeffects@latest my-app -- --template svelte-ts
```

`npm run build` проверяет типы файлов `.svelte` через `svelte-check`, которому нужен TypeScript 5: от него зависит шаблон.

### Начало с доменами

`domains-ts` — не разросшееся на TypeScript поле поиска из других шаблонов: он показывает, где живёт логика, когда в приложении несколько фич. Каждый домен — папка в `src/domains/`. В ней события домена, работа, которая их обрабатывает, и модуль, подключающий эту работу. React-компоненты только отправляют события и читают значения.

```bash
npm create nanoeffects@latest my-app -- --template domains-ts
```

| Путь | Задача |
| ---- | ------ |
| `src/bus.ts` | Создаёт шину. Не импортирует ни события, ни домены. |
| `src/app.ts` | Подключает домены через `modulePlugin`. |
| `src/domains/catalog/` | Поиск товаров: `catalog.ts` (события и действие с обработчиком), `catalog-handlers.ts` (`debounce` и `latest`), `catalog-module.ts`. |
| `src/domains/checkout/` | Оформление заказа: `checkout.ts` (задача), `checkout-handlers.ts` (`leading` и `retry`), `checkout-store.ts` (состояние, записываемое из исходов задачи), `checkout-module.ts`. |
| `src/ui/` | Компоненты. Ни один из них не вызывает поддельный сервер из `src/api.ts`. |

Пример побольше, чат, в котором части реагируют друг на друга, смотрите в [Чат с сущностями, фичами, модулями и небольшим сервером](chat-example.md). В нём больше слоёв, чем в `domains-ts`: когда домены должны реагировать друг на друга, он не даёт им импортировать друг друга, разделяя их на сущности и фичи.

Сами действия, задачи и модули объяснены в [Действиях, задачах и модулях](actions.md). Шаблон хранит найденные товары в провайдере Context с одним `useEventState`, а состояние заказа — в отдельном сторе: `useEventState` — [не стор](react.md#покажите-последнее-значение-события-как-состояние).

## Прочитайте файлы

Каждый шаблон, кроме `domains-ts`, делит код так же, как [руководство](guide.md): одна задача на файл. В TypeScript-шаблонах файлы заканчиваются на `.ts` (и `.tsx` у React-компонентов, `.vue` у компонентов Vue, `.svelte` у компонентов Svelte).

| Файл | Задача |
| ---- | ------ |
| `src/bus.js` | Создаёт шину. Не импортирует события. |
| `src/search.js` | Называет события через `createAction`. Не импортирует шину. |
| `src/search-handlers.js` | Обрабатывает события через `debounce` и `latest`. Знает и шину, и события. |
| `src/api.js` | Поддельный сервер. Замените его своими запросами. |

У каждого вызова nanoeffects в этих файлах есть комментарий о том, что он делает. Чтобы сделать проект своим, замените `src/api.js`, затем переименуйте события и обработчик.
