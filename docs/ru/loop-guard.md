# Обрыв цикла через `loopGuardPlugin`

> **[Уровень F](README.md#виды-проектов)**: платформа, SDK или долгоживущее приложение. Сначала прочитайте: [Плагины](plugins.md#подключение-плагина). Чтобы найти цикл до его обрыва, см. [Поиск и обрыв циклов событий](debugging-loops.md).

Два обработчика, которые отправляют события друг друга, не остановятся сами. Цикл из `await` и таймеров тратит процессор и сеть. Цикл из микрозадач вешает страницу: браузеру не достаётся ход, чтобы её отрисовать. Отчёт не остановит ни один из них. `loopGuardPlugin` остановит: он следит за цепочкой emit и отклоняет тот emit, который превысит предел.

Используйте его как страховку, в том числе в production. Трассировщик ему не нужен, и пока цепочка укладывается в пределы, он ничего не меняет. Плагин подключается по желанию: шина без него работает как раньше.

## Обрыв цикла

Плагин считает, сколько раз одно и то же событие стоит в цепочке emit, которая привела к этому emit. Цепочка идёт по `ctx.emit`, в том числе через `await`, таймеры и микрозадачи. Emit, который превысил бы предел, отклоняется, и цикл на этом заканчивается. Другие цепочки продолжают работу, а следующий emit извне начинает цепочку с нуля.

```js
// bus.js
import { createBus } from "nanoeffects";
import { loopGuardPlugin } from "nanoeffects/guard";

// loopGuardPlugin — отклоняет emit, который превысил бы предел цепочки
export const bus = createBus().use(
  loopGuardPlugin({
    maxRepeats: 50, // одно событие может стоять в цепочке 50 раз
    maxDepth: 1000, // цепочка может быть длиной 1000 emit, какие бы имена в ней ни были
  }),
);
```

| Параметр | По умолчанию | Что обрывает |
| -------- | ------------ | ------------ |
| `maxRepeats` | 50 | Одно событие слишком часто в одной цепочке: цикл. |
| `maxDepth` | 1000 | Слишком длинную цепочку, в том числе когда у каждого события новое имя (`step/${n}`). |
| `maxPerSecond` | нет | Emit одного события извне, вне обработчиков, которые идут слишком быстро ([ниже](#ограничение-emit-извне)). |
| `ignore` | нет | Имена событий, которые счётчик повторов пропускает ([ниже](#исключение-рекурсии)). |

## Выбор действия на пределе

`onLimit` говорит, что делает отклонённый emit. В обоих случаях плагин сообщает о находке один раз для каждого пути. В отчёте есть путь цикла и никогда нет payload.

```js
// bus.js
import { createBus } from "nanoeffects";
import { LoopError, loopGuardPlugin } from "nanoeffects/guard";

export const bus = createBus().use(
  loopGuardPlugin({
    onLimit: "drop", // "drop" (по умолчанию): emit не отправляется; "throw": он бросает LoopError
    // report — заменяет console.error по умолчанию
    report: (finding) => console.error(finding.limit, finding.path.join(" → ")),
  }),
);

// при onLimit: "throw" отклонённый emit бросает ошибку, а в ней указан путь
try {
  bus.emit("cart/changed");
} catch (error) {
  if (error instanceof LoopError) {
    console.log(error.limit, error.path);
  }
}
```

- **`"drop"`** — по умолчанию. Emit возвращается так, будто никто не слушал, поэтому в асинхронном обработчике не появляется новых ошибок.
- **`"throw"`** показывает цикл со стеком. В асинхронном обработчике ошибка превращается в rejection: обработайте её через `onError`.

Оборванный цикл может оставить состояние приложения недоделанным: обработчики, которые уже сработали, сделали свою часть, а те, что шли после обрыва, нет. Исправьте цикл, а плагин оставьте как страховку.

## Ограничение emit извне

У компонента, который отправляет событие на каждом рендере, цепочки нет: каждый emit приходит извне, вне обработчика. `maxPerSecond` считает такие emit для каждого события.

```js
// bus.js
import { createBus } from "nanoeffects";
import { loopGuardPlugin } from "nanoeffects/guard";

// maxPerSecond — emit одного события извне сверх 100 в секунду отклоняются
export const bus = createBus().use(loopGuardPlugin({ maxPerSecond: 100 }));
```

По умолчанию параметр выключен: всплеск из многих emit бывает нормальным (поток сообщений).

## Исключение рекурсии

Цепочка, которая повторяется намеренно, тоже обрывается. Обработчик, который отправляет `tree/visit` на каждом уровне дерева, или тот, который снова отправляет `tick` после таймера часами, превысит `maxRepeats`. Укажите его событие в `ignore`. `maxDepth` для него по-прежнему действует.

```js
// bus.js
import { createBus } from "nanoeffects";
import { loopGuardPlugin } from "nanoeffects/guard";

export const bus = createBus().use(
  loopGuardPlugin({
    ignore: ["tree/visit"], // имена или функция от имени
  }),
);
```

## Чего плагин не делает

- **Он не прерывает цепочку.** Он отклоняет один emit, на ребре, где превышен предел. Обработчики, которые уже работают, дорабатывают до конца.
- **Он следует за `ctx.emit`.** `bus.emit`, вызванный внутри обработчика, не входит в цепочку: он начинает новую со счётчиками с нуля. Внутри обработчиков используйте `ctx.emit`.
- **Он не ищет цикл.** Чтобы увидеть путь цикла и циклы, которые идут через компоненты, используйте `graphLogger` ([Поиск и обрыв циклов событий](debugging-loops.md)).
