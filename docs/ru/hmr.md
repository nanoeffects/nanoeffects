# Горячая перезагрузка и диагностика при разработке

> **Уровень F.** Сначала прочитайте: [Действия, задачи и модули](actions.md).

Используйте эту страницу при разработке с модулями и горячей перезагрузкой. Пропустите, пока не подключаете домены через `modulePlugin`.

Когда файл редактируют, сборщик загружает его новую версию и запускает её заново, а страница и остальной код остаются живыми. Для шины это может пойти не так тремя способами:

1. Файл, вызывающий `bus.on(...)`, подписывается второй раз.
2. Файл, создающий шину, создаёт новую.
3. Задачи старого кода продолжают выполняться.

## Заменяйте модули по имени

Подключение модуля с занятым именем заменяет подключённый. Старый модуль сначала отключается — а с ним его подписки, привязанные обработчики, подмодули и фоновые задачи (их сигналы прерываются). Новой версии файла модуля достаточно подключиться снова; ничего не копится.

- **Имена должны быть уникальными.** Имя означает «это новая версия того модуля», поэтому два разных модуля с одним именем заменяют друг друга. Имя также является типом задач модуля в трассировке.
- **Передавайте `signal` тому, что делает модуль.** Отключение прерывает задачи, но `fetch` или цикл, который игнорирует `ctx.signal`, продолжит работать со старым кодом.
- **Подмодули** (`m.use(...)`) заменяются по имени внутри родителя. Перезагрузка родителя заменяет его вместе со всеми детьми.
- Держите шину и приложение в файле, который не перезагружается (или в том, что ваш сборщик сохраняет между перезагрузками), чтобы перезагрузка не создавала новую шину, с которой другие файлы не общаются.

`bus.on` вне модуля возвращает функцию отписки: передайте её в dispose-хук вашего сборщика или положите подписку в модуль.

## Сообщайте об утечках через `devPlugin`

`bus.use(devPlugin())` сообщает о том, что легко упустить при разработке:

```js
import { createBus } from "nanoeffects";
import { modulePlugin } from "nanoeffects/actions";
import { devPlugin } from "nanoeffects/dev";

const bus = createBus();
bus.use(modulePlugin([userModule]));
// devPlugin — предупреждать о накопившихся слушателях; логировать подключение, замену и отключение модулей
// (он находит приложение modulePlugin на шине, в любом порядке этих двух)
bus.use(devPlugin());
```

- **Накопившиеся слушатели.** Когда добавлено и не отписано больше `maxListeners` (по умолчанию `10`) слушателей одного события, одно предупреждение называет событие и число. Счёт следует за функцией, которую возвращает `on`; `bus.off(event, fn)` не виден.
- **Модули.** Для приложения `modulePlugin` (или параметра `app`) он логирует `module "user" mounted`, `replaced`, когда подключён модуль с тем же именем, и `unmounted`. Сообщается только то, что идёт через `app.mount` и `app.unmount`, подмодули — нет.
- **Параметры.** `leaks: false` и `modules: false` отключают диагностику; `maxListeners` задаёт предел; `log` получает сообщения вместо консоли.
- **Отключение.** `bus.use(devPlugin(...))` возвращает функцию, которая останавливает диагностику и возвращает `bus.on` и `app.mount` на место.

Поведение он не меняет: он оборачивает `bus.on`, `app.mount` и `app.unmount` и добавляет сообщения.

### Оставьте импорт в production

`nanoeffects/dev` в production-сборке ничего не делает. `package.json` сопоставляет его с пустой сборкой по условию экспорта `production` (Vite и webpack задают его в режиме production), так что `bus.use(devPlugin())` можно оставить без защиты: он ничего не трогает и стоит несколько байт.

Если нужно, чтобы пропал даже вызов, защитите его (`if (import.meta.env.DEV)` в Vite). Приложение, которое не импортирует эту точку входа, её не несёт.
