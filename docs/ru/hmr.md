# Горячая перезагрузка и диагностика при разработке

> **Уровень F.** Сначала прочитайте: [Actions, jobs и модули](actions.md).

Страница для разработки с модулями и горячей перезагрузкой. Пропустите её, пока не подключаете домены через `modulePlugin`.

Когда вы правите файл, сборщик загружает его новую версию и запускает заново. Страница и остальной код продолжают работать. Для шины это грозит тремя проблемами:

1. Файл, вызывающий `bus.on(...)`, подписывается второй раз.
2. Файл, создающий шину, создаёт новую.
3. Задачи старого кода продолжают выполняться.

## Заменяйте модули по имени

Модуль с занятым именем заменяет подключённый. Сначала отключается старый модуль, а с ним его подписки, привязанные обработчики, подмодули и фоновые задачи (их сигналы прерываются). Новой версии файла достаточно подключиться снова: ничего не копится.

- **Имена должны быть уникальными.** Имя означает «это новая версия того модуля», поэтому два разных модуля с одним именем заменяют друг друга. В трассировке имя также служит типом задач модуля.
- **Передавайте `signal` в то, что делает модуль.** Отключение прерывает задачи, но `fetch` или цикл, который игнорирует `ctx.signal`, продолжит работать со старым кодом.
- **Подмодули** (`m.use(...)`) заменяются по имени внутри родителя. Родитель заменяется вместе со всеми подмодулями.
- Держите шину и приложение в файле, который не перезагружается (или который сборщик сохраняет между перезагрузками). Тогда перезагрузка не создаст новую шину, с которой другие файлы не связаны.

`bus.on` вне модуля возвращает функцию отписки. Вызывайте её в dispose-хуке сборщика или перенесите подписку в модуль.

## Сообщайте об утечках через `devPlugin`

`bus.use(devPlugin())` предупреждает о том, что легко упустить при разработке:

```js
import { createBus } from "nanoeffects";
import { modulePlugin } from "nanoeffects/actions";
import { devPlugin } from "nanoeffects/dev";

const bus = createBus();
bus.use(modulePlugin([userModule]));
// devPlugin — предупреждать о накопившихся подписках; логировать подключение, замену и отключение модулей
// (он находит приложение modulePlugin на шине, в любом порядке этих двух)
bus.use(devPlugin());
```

- **Накопившиеся подписки.** Если на одно событие подписано и не отписано больше `maxListeners` подписок (по умолчанию `10`), выходит одно предупреждение с названием события и числом. Счёт следит за функцией, которую возвращает `on`; `bus.off(event, fn)` он не видит.
- **Модули.** Для приложения `modulePlugin` (или параметра `app`) он логирует `module "user" mounted`, `replaced` (подключён модуль с тем же именем) и `unmounted`. В лог попадает только то, что идёт через `app.mount` и `app.unmount`; подмодули не попадают.
- **Параметры.** `leaks: false` и `modules: false` отключают диагностику; `maxListeners` задаёт предел; `log` получает сообщения вместо консоли.
- **Отключение.** `bus.use(devPlugin(...))` возвращает функцию, которая останавливает диагностику и возвращает `bus.on` и `app.mount` на место.

Поведение он не меняет: он оборачивает `bus.on`, `app.mount` и `app.unmount` и добавляет сообщения.

### Оставьте импорт в production

`nanoeffects/dev` в production-сборке ничего не делает. `package.json` сопоставляет его с пустой сборкой по условию экспорта `production` (Vite и webpack задают его в режиме production), поэтому `bus.use(devPlugin())` можно оставить без защиты: он ничего не трогает и весит несколько байт.

Чтобы убрать даже вызов, оберните его в проверку (`if (import.meta.env.DEV)` в Vite). Приложение, которое не импортирует эту точку входа, её не содержит.
