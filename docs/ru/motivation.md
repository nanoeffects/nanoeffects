# Зачем нужна nanoeffects

> **Уровень A.**

Вторая часть страницы — для авторов SDK, базовых библиотек и оболочек микрофронтендов, где общая зависимость — общий риск. Не уверены, что библиотека нужна? Откройте [Когда это не тот инструмент](#когда-это-не-тот-инструмент).

## Главная причина: логика вне UI

Компоненты с запросами, таймерами и гонками трудно тестировать и легко сломать. Обычное решение — вынести логику в сервисы и чистые функции. Тогда каждому сервису нужно одно и то же: отменять ненужную работу, повторять запросы, делиться зависимостями и показывать, что выполнилось и почему.

Привычные инструменты требуют многого: redux-saga описывает эту логику генераторами, RxJS — потоками и операторами. nanoeffects оставляет обычные `async`-функции и добавляет одну идею — `AbortSignal`. Шина событий — основа библиотеки, но не главная ценность: любой эмиттер отправляет события (`nanoevents` весит около 100 байт, [таких библиотек ещё десятки](https://github.com/gajus/sister#similar-libraries)). nanoeffects добавляет:

- отменяемые задачи, политики и эффекты;
- контекст — небольшой контейнер зависимостей;
- actions и модули, чтобы сгруппировать фичу;
- [трассировку](tracing.md) с адаптером для Redux DevTools.

Библиотека работает с тем, что уже есть в проекте: рецепты и небольшие адаптеры для [сторов](stores.md) (Redux Toolkit, Zustand, MobX, Pinia), мост к [RxJS](migrating-from-rxjs.md), помощники для [React](react.md), [Vue](vue.md) и [Svelte](svelte.md). Для старта ничего переписывать не нужно.

## Когда ограничение — общая библиотека

Общую библиотеку (SDK, базовый пакет, оболочку платформы) загружает множество приложений. Её зависимости становятся зависимостями приложений. Хуже всего библиотеки состояния и событий: они хранят **внутреннее состояние и идентичность** (стор, контекст, класс). Две копии или две версии такой библиотеки не сливаются и молча перестают видеть друг друга.

В Module Federation это видно сразу. Каждый remote добавляет свою копию, пока команды не договорятся о `singleton` и диапазоне версий. [Руководство Nx по версиям библиотек](https://nx.dev/docs/kb/manage-library-versions-with-module-federation) описывает последствия: библиотеки с внутренним состоянием конфликтуют, а метод, которого нет в одной версии, ломает вызывающих, написанных под другую.

Реальные случаи из библиотек, с которыми сравнивали nanoeffects:

| Библиотека | Что идёт не так | Источник |
| ---------- | --------------- | -------- |
| Redux, React Redux | Общая библиотека компонентов использует `react-redux`. Каждый микрофронтенд должен взять ту же версию, иначе `react-redux` «странно ломается». | [react-redux#1949](https://github.com/reduxjs/react-redux/issues/1949) |
| Redux | Стор доступен только внутри `Provider`. Каждому под-приложению нужен свой провайдер, но при внедрении модуля второй создавать нельзя. Редьюсеры, продублированные в хосте и модуле, усугубляют проблему. | [Redux on Module Federation](https://dev.to/manomano-tech-team/how-to-work-with-redux-on-module-federation-13gm) |
| Effector | Библиотека с `effector-react/scope`, собранная в другой проект, получает два экземпляра. `useStore` приложения не видит её `Provider`: «no scope found». | [effector#727](https://github.com/effector/effector/issues/727) |
| RxJS | Две копии дают два класса `Observable`. Типы одной версии не подходят другой, а операторы, добавленные в одну копию, отсутствуют в другой. Совет — «одна версия в `node_modules`». | [RxJS#2984](https://github.com/ReactiveX/rxjs/issues/2984), [neo4j-javascript-driver#978](https://github.com/neo4j/neo4j-javascript-driver/issues/978) |

Библиотека, которая **не** общий синглтон, так не ломается. У nanoeffects нет зависимостей и состояния уровня модуля: шина — объект, который вы создаёте сами. Две копии или версии пакета на одной странице дают две независимые шины. Глобально ничего не регистрируется, `Provider` не нужен, хост не выбирает версию за вас.

## Почему не альтернативы

| Вариант | Почему не подошёл |
| ------- | ----------------- |
| Redux (с сагами) | Стор и провайдер общие для всех потребителей — риск, описанный выше. В `redux-saga` к тому же нет простого способа получить ответ на событие: эффекты общаются через стор. |
| Effector | Граф с глобальной идентичностью. Если версия или scope в SDK и приложении разные, это затрагивает всю инфраструктуру. |
| Zustand | Хороший стор, но не способ запускать и отменять работу. Рядом с nanoeffects он — естественное место для состояния: см. [Сторы](stores.md). |
| RxJS | Гибкий, но экосистему (операторы, subjects, schedulers) придётся учить каждому, кто трогает SDK. Пакет не маленький: по данным [Bundlephobia](https://bundlephobia.com/package/rxjs) версия 7.8.2 весит 17,3 кБ в minify + gzip. |

## Что библиотека делает вместо этого

- **Нет зависимостей и глобального состояния.** Её безопасно поставлять в SDK рядом с кодом хост-приложения. Запись `singleton` в конфиге Module Federation не нужна.
- **Мала для жёсткого бюджета.** На весь сторонний код SDK часто дают несколько килобайт. `createBus` весит около 1,4 кБ в gzip (1,3 кБ в brotli). Политики, эффекты и actions — отдельные точки входа: импортируйте их, когда нужно. См. [Точки входа пакета](package.md).
- **Просто для старта.** Вся модель — `on` и `emit`. Отмена, повторы и остальное — обычные функции поверх. [Руководство](guide.md) и [Переход с redux-saga](migrating-from-saga.md) сопоставляют знакомые имена.
- **`emit` может вернуть ответ.** [Action с обработчиком](actions.md) возвращает результат, и один модуль может спросить другой и дождаться ответа. Голые события так не умеют. Именно этого больше всего не хватало вариантам на Redux.
- **Легко отлаживать.** Событийный код читать трудно: виден эффект, а не вызвавшее его событие. Каждая задача знает своего родителя, поэтому [трассировка](tracing.md) показывает цепочку событий. Логгеры работают с консолью, панелью Performance и Redux DevTools.

## Когда это не тот инструмент

Небольшому приложению с одним-двумя запросами библиотека не нужна: `fetch` в обработчике события годится, пока не появится первая гонка. nanoeffects не хранит состояние. Нужен стор? Оставьте Redux, Zustand или Effector, а async-работу отдайте шине: [Сторы](stores.md). Потоки уже везде? Оставьте RxJS: [nanoeffects рядом с RxJS](migrating-from-rxjs.md).
