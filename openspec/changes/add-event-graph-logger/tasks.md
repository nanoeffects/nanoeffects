## 6. Regression corpus from other libraries (`src/tests/regressions.cycles.test.ts`)

One test per report, named after it, with the link in a comment, in the style of the other `regressions.*` files. Each test builds the same shape on a nanoeffects bus, asserts that the logger reports (or, for a false-positive case, stays quiet), and where it makes sense that the app-level behavior (the number of handler calls) is what the shape dictates. "Open" means the issue is still open at the time of writing.

- [x] 6.1 Same result as trigger: an epic that listens to `X` and emits `X` ([redux-observable#283](https://github.com/redux-observable/redux-observable/issues/283), closed); two different actions that share one type string ([redux-saga#2356](https://github.com/redux-saga/redux-saga/issues/2356), closed). On a bus: a handler of `x` emits `x`; `createAction("x")` made twice; a job whose outcome type collides with its trigger; an action creator with the same `type` as a string event.
- [x] 6.2 A put back to the forker while it is still in the call ([redux-saga#277](https://github.com/redux-saga/redux-saga/issues/277), closed): a handler of `TEST` emits `TEST` once, guarded by a flag. Pin both sides: one re-entry is not a cycle (below `repeats`), and the same handler without the flag is; the re-entrant emit runs inside the first handler, and a listener added inside it is not called for the emit that was already running.
- [x] 6.3 A failure path that re-triggers its own callback ([xstate#4004](https://github.com/statelyai/xstate/issues/4004), closed): a handler throws, `onError` emits the same event again; a `job` whose `fail` listener re-emits the trigger (retry by event, forever); the `catchError` that returns the same source (the Angular/RxJS loop, a handler that re-emits on every failure). Report the loop through the error path, and keep the logger itself from being called again by its own failure (a throwing `onCycle`, a throwing logger).
- [x] 6.4 A missing target falls back to self ([xstate#3177](https://github.com/statelyai/xstate/issues/3177), closed): a router handler forwards `msg` to `targets.get(id)` and falls back to the same event when it is `undefined`. Reported as a self loop; and a version that has a target is quiet.
- [x] 6.5 Subscribing from inside a handler of the same source ([rxjs#6520](https://github.com/ReactiveX/rxjs/issues/6520), closed): a handler of `a` subscribes a new listener of `a` on every call and emits `a` (the listeners multiply); a state machine whose transition re-subscribes several calls deep. Report the loop, check that the graph stays bounded by names, and pin which listeners see the running emit.
- [x] 6.6 A timer loop that keeps running after its owner is gone ([rxjs#7148](https://github.com/ReactiveX/rxjs/issues/7148), open): `poll` whose function throws, aborted while waiting; a `debounce`/`throttle` timer after `app.unmount()`. This is not a cycle of events: assert that nothing is reported, that nothing runs after the abort, and that the task table of the logger is empty afterwards (no leak).
- [x] 6.7 The cost of the protection and of the report ([effector#331](https://github.com/effector/effector/issues/331), closed; the maintainer noted that a synchronous console was the real cost): 10 000 turns in one tick finish in bounded time with the default `console.warn`, one warning is written, and `onCycle` that logs a lot does not turn the report into a second loop.
- [x] 6.8 A component effect that reads and writes the same thing ([svelte#15398](https://github.com/sveltejs/svelte/issues/15398), closed; [zustand#1020](https://github.com/pmndrs/zustand/issues/1020), closed; React "Maximum update depth exceeded"): in React tests, a `useEffect` without deps that emits; deps that change on every render (a new object each time) with and without `equals` of `useEmitter`; a store updated from a subscription callback with a new object each time. Reported as a storm or a cycle, and absent when `equals` stops it.
- [x] 6.9 A self-referencing derivation after inheritance ([mobx#4660](https://github.com/mobxjs/mobx/issues/4660), closed): a module extended by `m.use` of another module that listens to the same event, and a module replaced by name (hot reload) that leaves the old listener alive. No false cycle from a handler bound twice, and no doubled counts in the graph after the replace.
- [x] 6.10 A broken state after an exception ([preactjs/signals#995](https://github.com/preactjs/signals/issues/995), open): a handler throws in the middle of a chain and the next runs of the same chain must not report a cycle; the same for `cancel` and `drop`. Checks that the table of live tasks frees on every way a task ends.
- [x] 6.11 Cleanup that triggers the thing it cleans ([vue#6538](https://github.com/vuejs/core/issues/6538), open): a component whose unmount cleanup emits an event, a handler of which causes a re-mount, whose cleanup emits again. Reported as a cycle or a storm; stops after the component is gone.
- [x] 6.12 An external event closes the loop ([TanStack Query#2868](https://github.com/TanStack/query/issues/2868), closed): `window` `focus` handler emits `refetch`, whose handler triggers a new `focus` (an alert or a dispatched event). A storm from outside any task, reported with the type of the event and not as a chain; `traceGroupId` joins the roots when it is set.
- [x] 6.13 Synchronous chains that overflow the stack and listener changes during an emit (Node `EventEmitter` three-event chains, [expo#28149](https://github.com/expo/expo/pull/28149), the `nextgen-events` fix): a loop of three sync events overflows the stack and the report comes first; unsubscribing inside the unsubscribe path; a listener that removes itself or others during an emit; the same chain broken with `queueMicrotask`/`setTimeout` (reported across the gap).
- [x] 6.14 Add a short "known loops" table to the docs (the shape, how the report looks, how to break it: a different event for the result, `equals`, a guard flag, `latest`) in `docs/tracing.md` and the Russian page; `pnpm docs:check` passes.
