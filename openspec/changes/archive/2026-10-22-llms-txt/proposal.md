# Proposal: `llms.txt` and `llms-full.txt` for AI assistants

## Why

More and more users write code with an assistant that has never seen nanoeffects, or knows an old version. It guesses the API (`bus.subscribe`, `retry(fn)` without `ctx`) and the user debugs the guess. The library has good, type-checked docs (`pnpm docs:check`), but an assistant needs them in one predictable place: a short index to choose pages and a single file it can load whole. The `llms.txt` convention gives both.

## What Changes

- `llms.txt` at the repository and package root, written by hand: the name, a one-paragraph summary with the rules an assistant gets wrong most (ESM only, `ctx` first in effects, `emit` returns the command result), and links to the `docs/` pages grouped by project need, in reading order.
- `llms-full.txt`: generated by `scripts/llms-full.mjs` from the pages that `llms.txt` links to, in that order, each under a `Source:` line. It is built by `pnpm build`, ignored by git, and published.
- `package.json` `files` lists both. The package already ships `docs/`, so a reader of `node_modules/nanoeffects` can follow the relative links, and a web reader gets one file from `unpkg.com/nanoeffects/llms-full.txt`.
- A check that fails when `llms.txt` links to a missing page, or a page of `docs/` is missing from `llms.txt`, so a new docs page is not forgotten. It runs in `pnpm verify` and CI together with `docs:check`.
- `docs/package.md` (reference) gets one paragraph that says where the files are. README is not changed.

## Capabilities

### New Capabilities
- `llm-docs`: machine-readable documentation entry points of the package, an index and a full text, kept in step with `docs/`.

### Modified Capabilities

None.

## Non-goals

- Anything in `src/`, or a change of the docs pages for assistants only.
- A docs site, an MCP server, Context7 registration or a `.cursor` rules package.
- Per-page `.md` copies, or rewriting the relative links inside the concatenated text.
- A link in the README: it is for levels A and B, and `llms.txt` is not a step of installing or running the bus.
- Token counting, trimming or summarizing of the docs.

## Impact

- New: `llms.txt`, `scripts/llms-full.mjs`, its test (`scripts/llms-full.test.mjs`).
- Edited: `package.json` (`files`, `build`, `llms:check` in `verify`), `.gitignore`, `.github/workflows/ci.yml`, `docs/package.md`, `docs/README.md` (if it lists pages `llms.txt` must match), `AGENTS.md` (Commands, Layout, a rule for new docs pages), `CHANGELOG.md`.
- The tarball grows by about 80 kB before compression (about 20 kB gzip). The `size` limits count only the entries in `dist/` and do not change.
